# LeetCode 141 环形链表 README.md

> 
> 题目：141. Linked List Cycle
> 难度：简单
> 题目链接：[https://leetcode.cn/problems/linked-list-cycle/](https://leetcode.cn/problems/linked-list-cycle/)

## 解题思路（个人大白话）

采用**快慢指针（Floyd 判圈算法，龟兔赛跑）**，满足题目进阶 O (1) 常量内存的要求。

1. 慢指针 `slow`，每次走 1 步；快指针 `fast`，每次一次性走 2 步。
2. 链表无环：快指针会最先走到链表末尾 `NULL`，循环结束，返回 false。
3. 链表存在环：两个指针会进入环形区域，快指针速度更快，最终一定会在环内追上慢指针，两指针地址相等，返回 true。

> 
> 类比：环形跑道，兔子（fast）跑的更快，一定会追上乌龟（slow）；如果是直跑道，兔子直接跑到终点。

##  复杂度分析

- 时间复杂度：\(O(n)\)，n 为链表节点数量，最多遍历链表一次
- 空间复杂度：\(O(1)\)，只定义两个指针变量，不额外开辟内存，符合进阶要求

##  测试样例

样例 1：`head = [3,2,0,-4], pos = 1`
输出：`true`，链表尾节点 - 4 连接到下标 1 的节点 2，存在环

样例 2：`head = [1,2], pos = 0`
输出：`true`，尾节点 2 连接回头节点 1

样例 3：`head = [1], pos = -1`
输出：`false`，单个节点，无环

##  踩坑记录

1. while 循环条件必须写 `fast != NULL && fast->next != NULL`。如果缺少 `fast->next != NULL`，访问`fast->next->next`会触发空指针访问，直接程序崩溃。
2. 判断相遇用 `slow == fast`，**比较的是节点指针地址，不是节点内 val 值**，节点的值有可能重复，不能用 val 判断。
3. 空链表（head=NULL）代码天然兼容，直接返回 false。
4. 本地构造环形链表测试时，**不能直接循环 free 释放全部节点**，会陷入无限循环，造成内存泄漏。
5. 不要使用哈希表解法：哈希表需要额外内存，无法满足 O (1) 空间的进阶要求。
